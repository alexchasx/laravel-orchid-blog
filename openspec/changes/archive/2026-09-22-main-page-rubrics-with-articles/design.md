## Context

Главная страница (`resources/views/index.blade.php`) рендерит секцию «Исследуйте по темам» фиксированным списком из 4 тем со ссылками на slug (`route('showByRubric', 'architecture')` и т.п.). Маршрут `rubric/{rubric}` использует implicit model binding по `id`, поэтому slug-ссылки не резолвятся. Все страницы-списки (главная, поиск по `?search=`, рубрика, тег, notpublic) рендерят один шаблон `index.blade.php` из четырёх методов `ArticleController`.

Модель `Rubric` (поля `title`, `slug`, `description`) имеет связь `articles()` — hasMany. Видимость статей на публичных страницах задаёт `Article::published()` (`is_published = true` и `published_at <= now()`, сравнение по полному timestamp).

## Goals / Non-Goals

**Goals:**
- Секция Topics показывает только рубрики с опубликованными статьями
- Список формируется из БД — новые рубрики появляются автоматически, пустые скрываются
- Секция скрывается целиком, если подходящих рубрик нет
- Единая точка получения данных без дублирования в контроллерах

**Non-Goals:**
- Фильтрация списка меток (тегов)
- Фильтрация legacy-сайдбара `includes/sidebar.blade.php` (не используется в techlog-layout)
- Изменение поведения страниц `/rubric/{rubric}`, `/tag/{tag}`, `/notpublic`
- Смена route key маршрута `showByRubric` на `slug`

## Decisions

### D1: Критерий «рубрика со статьями» — только опубликованные статьи

```
Решение: Рубрика попадает в список, если у неё есть хотя бы одна статья,
удовлетворяющая Article::published() — is_published = true и published_at <= now().

Альтернатива: считать любые статьи, включая черновики.
Проблема: на публичной странице появляются рубрики, ведущие на пустые
или скрытые списки; противоречит поведению остальных выборок.

Рациона: согласованность с Article::published() и видимым контентом.
```

### D2: Динамический список рубрик вместо хардкода

```
Решение: секция Topics рендерит рубрики из БД через цикл; ссылка —
route('showByRubric', $rubric) — binding по id модели.

Альтернатива: оставить 4 фиксированные темы и только скрывать непустые.
Проблема: не выполняется требование «выводить в списке категорий только те,
которые имеют связанные статьи» для произвольного набора рубрик.

Рациона: новые рубрики автоматически появляются, пустые — скрываются.
Побочно чинит нерезолвящиеся slug-ссылки хардкода.
```

### D3: Передача данных через View Composer

```
Решение: View Composer RubricsComposer для вьюхи index, данные из
ArticleService::getRubricsWithArticles(); регистрация в AppServiceProvider::boot().

Альтернатива 1: добавлять 'rubrics' => ... в каждый из 4 методов ArticleController
(index, showNotPublic, showByRubric, showByTag).
Проблема: дублирование и риск рассинхрона при добавлении новых методов.

Альтернатива 2: запрос Rubric прямо в Blade-шаблоне.
Проблема: доменная логика в представлении.

Рациона: единая точка внедрения; шаблон остаётся декларативным.
```

### D4: Пустая секция скрывается целиком

```
Решение: секция оборачивается в @if ($rubrics->isNotEmpty()); при пустом
списке ни секция, ни её заголовок не выводятся.

Альтернатива: выводить заголовок с пустой сеткой.
Проблема: пустая секция выглядит как дефект вёрстки.

Рациона: предсказуемое поведение при отсутствии контента.
```

### D5: Порядок рубрик — алфавитный

```
Решение: orderBy('title'); номер карточки (01, 02, …) — индекс цикла.

Альтернатива: сортировка по числу статей (articles_count desc).
Проблема: порядок «скачет» при добавлении статей.

Рациона: стабильный, предсказуемый порядок.
```

## Migration Strategy

Без миграций и изменений схемы БД. Существующие рубрики и статьи не затрагиваются: меняется только выборка и шаблон главной страницы.
