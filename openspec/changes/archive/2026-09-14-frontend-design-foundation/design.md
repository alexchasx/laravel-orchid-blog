## Context

Текущее состояние стилей публичного блога (подробности и мотивация — см. proposal.md):

- [`resources/sass/style.scss`](resources/sass/style.scss) — монолит на ~390 строк: опечатки `@media (max-widht: ...)` (строки 86–105) делают брейкпоинты нерабочими; float-хелперы `.left`/`.right`/`.clearfix`; чекбокс-хак меню `#menuCheck:checked + .menu`; `font-size: 12px` на мобильных (строка 159); баг `.main_block { max-width: 1170; }` без единиц измерения (строка 81); Bootstrap-стиль алертов и пагинации.
- [`resources/sass/_variables.scss`](resources/sass/_variables.scss) — SCSS-переменные Bootstrap-эпохи (`$body-bg: #f8fafc`, `$hover-link-color: chocolate`, шрифт Nunito).
- [`resources/views/layouts/base.blade.php:6`](resources/views/layouts/base.blade.php:6) — viewport запрещает зум (`maximum-scale=1.0, user-scalable=0`).
- Сборка: Vite 6, входная точка кастомных стилей — `resources/sass/style.scss` (спека `frontend-build`, R2/R3); Tailwind подключён через `resources/css/app.css`, но публичный блог его не использует; Alpine 3 подключён.

Ограничения, которые нельзя нарушать: путь входной точки `style.scss` и директива `@vite` в шаблонах неизменны; `_variables.scss` и `normalize.css` сохраняются (спека `frontend-build`, R5); админка Orchid не затрагивается.

## Goals / Non-Goals

**Goals:**
- Единый источник дизайн-токенов на CSS custom properties (`:root`), покрывающих цвет, типографику, spacing, радиусы, тени.
- Модульная структура SCSS с тонким оркестратором, сохраняющая рабочую сборку Vite на каждом шаге.
- Базовая типографика: системный стек шрифтов, `clamp()` для заголовков, базовый `font-size` ≥ 16px.
- Доступный viewport: зум не запрещён.
- Сохранение внешнего вида и разметки страниц на уровне структуры — меняются только стили и метатег viewport.

**Non-Goals:**
- Фаза 2 плана: сетка `.wrap` 70/30, sticky-сайдбар, бургер-меню, футер, пагинация — не реализуются.
- Тёмная тема (Фаза 5): `_dark.scss` создаётся только как пустой каркас.
- Компоненты (Фаза 3), адаптивность/доступность (Фаза 4), производительность (Фаза 6), QA (Фаза 7) — вне скоупа.
- Изменения JS/Alpine, Tailwind-конфигурации, перевод наследуемых стилей на Tailwind-утилиты.
- Удаление мёртвого CSS (только инвентаризация с пометками в рамках Фазы 0).

## Decisions

### D1: CSS custom properties в `_tokens.scss` + легаси-слой `_variables.scss`
Новый файл `_tokens.scss` объявляет в `:root` токены: `--color-*` (нейтральная база, акцентный цвет, состояния success/warning/danger, текст/фон), `--font-sans`, `--font-size-*`, `--space-*` (шкала 4/8/12/16/24/32/48/64), `--radius-*`, `--shadow-*`. Значения берутся из текущей палитры `_variables.scss`, чтобы визуально ничего не изменилось.
`_variables.scss` сохраняется без удаления: наследуемые стили в `style.scss` (и партиалах) продолжают использовать SCSS-переменные. Цвета, задействованные в `_variables.scss`, дублируются в токены (одна строка-комментарий «legacy» указывает на соответствие).
*Альтернатива:* удалить `_variables.scss` и переписать все использования на токены — потребовало бы тотального рефакторинга наследуемых стилей и выходит за рамки Фазы 1.

### D2: `style.scss` становится оркестратором на `@use`
Порядок подключения в `style.scss`:
```scss
@use 'normalize' as *;      // via ../css/normalize.css (см. D3)
@use 'variables' as *;      // легаси SCSS-переменные
@use 'tokens';              // CSS custom properties
@use 'base';
@use 'layout';
@use 'components';
@use 'dark';
```
Партиалы, использующие SCSS-переменные из `_variables.scss`, объявляют `@use 'variables' as *` самостоятельно — это обязательное условие при переходе с `@import` (иначе undefined variable).
*Альтернатива:* оставить `@import` — Sass его деприцирует, а новая модульная структура рассчитана на `@use`.

### D3: Нормализация переезжает в `_base.scss`
Импорт `../css/normalize.css` переносится из `style.scss` в `_base.scss` (через `@use '../css/normalize.css' as *` либо физический `@import` — решение по факту сборки sass, допустимы оба варианта, главное — сохранить поведение). В `_base.scss` также живут базовые стили: reset-дополнения, ссылки, типографика по умолчанию.

### D4: Системный шрифтовой стек и fluid-типографика
`_base.scss` задаёт `font-family: var(--font-sans)` со стеком `system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif`. Заголовки h1–h6 получают `clamp()` (например `h1 { font-size: clamp(1.75rem, 1.25rem + 2vw, 2.5rem); }`), базовый `font-size: 16px` на `html`/`body`. Из `style.scss` удаляется блок `@media screen and (max-width: 900px) { html, body { font-size: 12px; } }`.
*Альтернатива:* оставить Nunito/Arial — противоречит цели обновления дизайна и кросс-платформенности.

### D5: Viewport без запрета зума
В `base.blade.php` метатег меняется на `width=device-width, initial-scale=1.0` (без `maximum-scale` и `user-scalable`). Это единственное изменение разметки в change.

### D6: Каркас `_dark.scss`
Создаётся пустой партиал с комментарием «Тёмная тема — Фаза 5», подключается в оркестратор, чтобы целевая архитектура (из плана) была зафиксирована структурно с самого начала.

### D7: Исправление очевидных багов фундамента
В рамках Фазы 1 чинятся точечные ошибки, не меняющие внешний вид: `.main_block { max-width: 1170; }` → `1170px`; опечатки `max-widht` убираются путём перевода медиазапросов в рабочую нотацию или удаления (замена на min-width mobile-first — только если это не меняет текущий вид; иначе — удаление нерабочих правил с фиксацией в changelog). Решение по каждому правилу принимается на основе скриншотов Фазы 0.

## Risks / Trade-offs

- [Регрессия наследуемых стилей при разбиении монолита] → Скриншоты до/после из Фазы 0; перенос блоков партиями с проверкой `npm run build` и визуальным контролем после каждого коммита.
- [Переход `@import` → `@use` вызывает undefined variable в партиалах] → Каждый партиал с использованием переменных объявляет `@use 'variables' as *`; сборка прогоняется после каждого подключения нового партиала.
- [Изменение viewport может сказаться на вёрстке при зуме] → Ожидаемое и желаемое поведение (доступность); при визуальных артефактах на 320px применяется фикс в `_layout.scss`, но полноценная адаптивность — Фаза 4.
- [CSS custom properties не поддерживаются очень старыми браузерами] → Приемлемо: целевые браузеры — актуальные Chrome/Firefox/Safari/Edge; политика плана — современные браузеры.
- [Конфликт с Tailwind preflight при будущем использовании `app.css`] → Публичный блог не подключает `app.css`; конфликт возможен только при смешивании в одном элементе — придерживаемся правила «не смешивать» из плана.

## Migration Plan

1. **Фаза 0 (аудит, без кода):** инвентаризация Blade-шаблонов и классов → список используемых/мёртвых классов; скриншоты index/article/contact на 375/768/1280px; Lighthouse-замер до изменений.
2. **Шаг 1:** создать `_tokens.scss` с полным набором токенов (значения из текущей палитры); подключить в `style.scss`; проверить сборку (внешний вид не меняется).
3. **Шаг 2:** выделить `_base.scss` (нормализация + базовые стили), `_layout.scss` (`.main_block`, `.wrap`, шапка, футер), `_components.scss` (карточки, алерты, пагинация, формы); `style.scss` постепенно превращается в оркестратор; после каждого переноса — `npm run build`.
4. **Шаг 3:** типографика (системный стек, clamp, 16px) и исправление багов (`1170px`, `max-widht`); контроль по скриншотам.
5. **Шаг 4:** viewport в `base.blade.php`; контроль на 320px–1920px и пинч-зум.
6. **Откат:** git revert пошагово; каждый шаг — отдельный коммит.
