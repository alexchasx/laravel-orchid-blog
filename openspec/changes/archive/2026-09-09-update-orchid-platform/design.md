## Context

Проект на Laravel 9.28 / Orchid 12.6 (lock-файл), но [`composer.json`](../../composer.json) уже объявляет Laravel `^13.0` и Orchid `^14.53`. `vendor/` не установлен, структура приложения (`bootstrap/app.php`, kernels, exception handler, `Auth::routes()`) в стиле Laravel 9, код панели в стиле Orchid 12.

Мотивация и требования — в `proposal.md` и `specs/orchid-platform/spec.md`.

Целевой стек:
- `laravel/framework` 13.x (последний стабильный), требует PHP `^8.3`;
- `orchid/platform` 14.53, совместим с Laravel `^10–13`;
- PHP: хост 8.4.25, Docker `php:8.5-fpm`; `composer.json` заявляет `^8.5`.

**Scope:** только ядро Laravel + код Orchid. Фронтенд (Vite) и модернизация auth (Breeze/Fortify) вынесены в отдельные изменения.

## Goals / Non-Goals

**Goals:**
- Привести зависимости к целевому стеку: пересобрать `composer.lock`, установить `vendor/`, разрешить конфликты пакетов.
- Мигрировать ядро на структуру Laravel 11+/13: новый `bootstrap/app.php`, `bootstrap/providers.php`, удаление `app/Http/Kernel.php` и `app/Console/Kernel.php`, современный exception handler.
- Сохранить работоспособность аутентификации: заменить `Auth::routes()` явными маршрутами на существующие контроллеры.
- Адаптировать код панели под Orchid 14 (`config/platform.php`, `PlatformProvider`, экраны/layout/presenters/фильтры, `routes/platform.php`).

**Non-Goals:**
- Не мигрировать фронтенд на Vite (остаётся `laravel-mix`).
- Не переписывать аутентификацию на Breeze/Fortify (только минимальная правка маршрутов).
- Не менять бизнес-логику моделей/контроллеров публичной части иначе, чем требуется для работы на новом стеке.

## Decisions

**D1: Сначала Composer, потом код.**
Порядок работ: пересборка зависимостей и установка `vendor/` даёт актуальные сигнатуры Laravel 13/Orchid 14, по которым правятся bootstrap/kernels и код панели. Обратный порядок (правка кода до установки) невозможен без знания целевых API.

**D2: Миграция ядра через `bootstrap/app.php` (стандарт Laravel 11+).**
Middleware, группы middleware, маршруты (`web`, `console`, custom) и обработчик исключений регистрируются через `->withMiddleware()`, `->withRouting()`, `->withExceptions()`; провайдеры — через `bootstrap/providers.php`. Старые `app/Http/Kernel.php` и `app/Console/Kernel.php` удаляются. Это обязательное условие запуска на Laravel 13.

**D3: Auth без редизайна — только перевод маршрутов.**
`Auth::routes()` удалён в Laravel 11+. Вместо него в `routes/web.php` явно объявляются маршруты логина/регистрации/восстановления пароля на существующие контроллеры. Логика аутентификации не меняется; полноценная модернизация — вне scope.

**D4: Адаптация Orchid точечная, по фактическим ошибкам API.**
Ориентир — официальная документация Orchid 14 и актуальные сигнатуры после установки. `config/platform.php` обновляется под новые ключи; `PlatformProvider`, экраны, layout, presenter, фильтры правятся при выявлении несовместимости (минимально инвазивно).

**D5: Фронтенд остаётся на `laravel-mix`.**
Vite — отдельное изменение. `laravel-mix` не зависит от версии Laravel напрямую, поэтому миграция ядра его не ломает.

**D6: Платформенное требование PHP.**
Так как `composer.json` требует PHP `^8.5`, а хост даёт 8.4, локальный `composer update` выполняется либо в Docker (PHP 8.5), либо с флагом игнорирования платформенных требований. Окружение для фактической установки фиксируется в задачах.

## Risks / Trade-offs

- [Конфликты пакетов при пересборке lock (`laravel/ui`, `mews/captcha` и др. могут не поддерживать Laravel 13)] → Разрешать граф зависимостей: корректировать объявления или удалять несовместимые пакеты; результат фиксировать в tasks.md.
- [Замена `Auth::routes()` может нарушить существующие маршруты/именования] → Явно воспроизвести прежние маршруты и имена; проверить формы входа/регистрации.
- [Orchid 12→14 содержит breaking changes в экранах/layout/провайдере] → Правки по фактическим ошибкам после установки; минимизировать изменения.
- [Несоответствие PHP (хост 8.4 vs требование 8.5) блокирует Composer] → Использовать Docker или флаг `--ignore-platform-req` для локальной сборки; задокументировать.
- [Публичные ассеты (`public/mix-manifest.json`) ссылаются на старые сборки] → Фронтенд вне scope; работоспособность публичной части проверяется, но пересборка ассетов не планируется.

## Migration Plan

1. Пересобрать зависимости: `composer update` (в Docker или с игнорированием платформенного требования PHP) → обновлённый `composer.lock` и `vendor/`.
2. Разрешить конфликты пакетов в `composer.json` (при необходимости удалить/поднять `laravel/ui` и др.), повторить `composer update`.
3. Мигрировать ядро: новый `bootstrap/app.php`, создать `bootstrap/providers.php`, удалить `app/Http/Kernel.php` и `app/Console/Kernel.php`, модернизировать `app/Exceptions/Handler.php`, адаптировать конфиги.
4. Заменить `Auth::routes()` в `routes/web.php` явными маршрутами.
5. Адаптировать Orchid: `config/platform.php`, `app/Orchid/*`, `routes/platform.php` под 14.x.
6. Проверка: `php artisan route:list`, `php artisan about`, запуск панели и публичных страниц; исправление ошибок.

**Откат:** миграция атомарна через git — возврат ветки к состоянию до изменений. `composer.lock` пересобирается повторно при необходимости вернуться к старому стеку.

## Open Questions

- Конкретные несовместимые пакеты станут известны после первого `composer update`; решение об их судьбе принимается по факту.
- Требуется ли корректировка `config.platform.php`/`php` в `composer.json` под фактический PHP окружения — решается при установке.
