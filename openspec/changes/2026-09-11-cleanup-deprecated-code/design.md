## Context

Проект уже работает на Laravel 13 / Orchid 14.53 (см. proposal.md — Why). Текущий код панели использует депрецированные символы Orchid 14 (`UserSwitch`, `getStatusPermission()`) и депрецированный `Request::get()` (Laravel 13). Также остался неиспользуемый auth-код старого стека.

## Goals / Non-Goals

**Goals:**
- Устранить все найденные депрекации под текущие версии без изменения внешнего поведения панели.
- Удалить мёртвый auth-слой.
- Не менять версии зависимостей и не трогать публичную часть сайта.

**Non-Goals:**
- Модернизация самой аутентификации (переход на Fortify/новый поток) — вне рамок.
- Полноценный прогон `phpstan`/`larastan` — требует установки dev-зависимостей и PHP >= 8.5 (локально 8.4); вынесено отдельно.

## Decisions

- **`UserSwitch` → `Impersonation`**: класс `Orchid\Access\UserSwitch` объявлен deprecated и является алиасом `Orchid\Access\Impersonation`. Замена сводится к смене `use`-импорта и вызова в `loginAs()` экрана пользователя. Альтернатива — оставить как есть до удаления класса; отклонено, т.к. цель — убрать депрекации.
- **`getStatusPermission()` → `statusOfPermissions()`**: метод с сингулярным именем deprecated (см. `vendor/orchid/platform/src/Access/StatusAccess.php`). Замена — только переименование вызова в экранах пользователя и роли; возвращаемый тип идентичен.
- **`Request::get()` → `input()`**: депрекация Laravel 13 (`Request::get` → `input`). Заменяются только вызовы на объекте `Illuminate\Http\Request` в экранах/фильтре панели. Вызовы `->get()` на `Collection`/`Repository` (например, в `RolePermissionLayout`) остаются нетронутыми.
- **Удаление мёртвого auth-кода**: удаляются 6 неиспользуемых контроллеров и старые представления. Проверка отсутствия ссылок выполнена поиском по `app/` и `routes/`. Действующие маршруты Breeze используют только актуальные контроллеры. Демо-экраны Orchid (`app/Orchid/Screens/Examples/*`, `app/Orchid/Layouts/Examples/*`) остаются без изменений — они вне охвата.

## Risks / Trade-offs

- [Невозможность локального запуска `composer install` из-за PHP 8.4 vs требование `^8.5`] → правки выполняются на основе чтения vendor-исходников; финальная верификация запуском приложения выполняется в Docker `php:8.5-fpm` либо с `--ignore-platform-req=php`.
- [Пропуск `->get()` на Collection/Repository при массовой замене] → точечная замена только по объектам `Request`; каждый файл проверяется вручную.
- [Ручной скан вместо phpstan может не покрыть все депрекации] → в tasks добавлена финальная проверка `php artisan route:list` и grep по депрецированным символам.

## Migration Plan

1. Внести правки депрекаций Orchid и Laravel в экраны/фильтры панели.
2. Удалить мёртвые auth-контроллеры и старые представления.
3. Верификация: `php artisan route:list`, grep-проверки на отсутствие депрецированных символов; при необходимости прогон в Docker на PHP 8.5.

Откат: изменения полностью обратимы через VCS; удаление файлов легко восстановить из истории.
