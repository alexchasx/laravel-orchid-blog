# План обновления дизайна: современный, адаптивный, кросс-платформенный

> Документ-план (не реализация). Цель: привести публичный фронтенд блога
> (Laravel + Blade + Vite + SCSS/Tailwind + Alpine) к современному виду,
> мобильной адаптивности и корректной работе на всех основных платформах.

## 1. Цели

1. Современный визуальный стиль: чистая типографика, аккуратная палитра, карточки, отступы по шкале.
2. Полная адаптивность: mobile-first, от 320px до 4K.
3. Кросс-платформенность: браузеры (Chrome/Firefox/Safari/Edge), iOS/Android, темная тема ОС.
4. Доступность (a11y): читаемый контраст, фокус-состояния, зум, семантика.
5. Сохранение функциональности: контент, комментарии, формы, рубрики/теги, админка Orchid не затрагивается.

## 2. Аудит текущего состояния (факты из кода)

| Область | Сейчас | Проблема |
|---|---|---|
| Сборка | Vite 6, Tailwind 3.4 (`resources/css/app.css`), SCSS `resources/sass/style.scss` (393 стр.), Alpine 3 | Tailwind подключен, но фактически стили — самописный SCSS; двойная система |
| Макет | `.wrap` grid 70/30; float `.left`/`.right`, `.clearfix` | Устаревшие приёмы, сайдбар не липкий |
| Медиазапросы | `@media (max-widht: ...)` в `style.scss` | Опечатка `widht` — брейкпоинты НЕ работают |
| Навигация | Чекбокс-хак `#menuCheck` + CSS | Без JS, нет анимации, нет ARIA, закрытие по клику вне меню не работает |
| Viewport | `maximum-scale=1.0, user-scalable=0` (`layouts/base.blade.php`) | Запрет зума — нарушение доступности |
| Типографика | Arial/Nunito, `font-size: 12px` на мобильных | Нет fluid-типа, мелкий текст |
| Палитра | Bootstrap-эпоха: `#f8fafc`, `#eee`, hover `chocolate` | Устаревшая, нет токенов, нет тёмной темы |
| Иконки | FontAwesome статика в `public/fonts` | Лишний вес, можно заменить инлайн-SVG |
| Компоненты | Blade-инклюды: sidebar, comments, donate, meta_tags | Смешение разметки и стилей, нет переиспользуемых компонентов |

## 3. Целевая архитектура стилей

```
resources/
  css/app.css            -> @tailwind base/components/utilities + @layer компоненты
  sass/_tokens.scss      -> CSS-переменные: цвет, тип, радиусы, тени, spacing
  sass/_base.scss        -> reset/нормализация, типографика, ссылки
  sass/_layout.scss      -> сетка, header, nav, footer
  sass/_components.scss  -> карточки, кнопки, формы, пагинация, алерты
  sass/_dark.scss        -> токены тёмной темы
  sass/style.scss        -> только @use/@import модулей (тонкий оркестратор)
```

Принцип: единый источник дизайн-токенов (CSS custom properties) +
утилиты Tailwind для новой разметки + модульный SCSS для наследуемого.
Отказ от float и чекбокс-хака в пользу Grid/Flexbox + Alpine.

## 4. Дизайн-система (токены)

- **Цвет**: нейтральная база (slate/gray), 1 акцентный (например `indigo-600`/`sky-600`),
  состояния (success/warning/danger) с контрастом >= 4.5:1.
- **Тёмная тема**: токены через `prefers-color-scheme: dark` + ручной переключатель (Alpine + localStorage).
- **Типографика**: системный стек (`system-ui, -apple-system, Segoe UI, Roboto, ...`),
  fluid-размеры `clamp()` для заголовков, `font-size` базовый не менее 16px.
- **Spacing**: шкала 4/8/12/16/24/32/48/64 (кратна 4).
- **Радиусы/тени**: единые токены (`--radius-md`, `--shadow-sm` и т.д.).
- **Брейкпоинты**: 640 / 768 / 1024 / 1280 (mobile-first, `min-width`).

## 5. Фазы работ

### Фаза 0 — Подготовка (0.5–1 день)
- [ ] Инвентаризация всех Blade-шаблонов и классов (найти мёртвый CSS).
- [ ] Скриншоты текущего вида (десктоп/мобайл/планшет) для регрессии.
- [ ] Снять замер производительности (Lighthouse, WebPageTest) до изменений.

### Фаза 1 — Фундамент и токены (1–2 дня)
- [ ] Создать `_tokens.scss` с CSS-переменными; перенести цвета из `_variables.scss`.
- [ ] Переписать базовую типографику: системный шрифт, `clamp()`, заголовки.
- [ ] Исправить viewport: убрать запрет зума в `layouts/base.blade.php`.
- [ ] Подключить модульную структуру SCSS, сохранив сборку Vite.

### Фаза 2 — Макет и навигация (2–3 дня)
- [ ] `.wrap`: остаётся grid 70/30 на десктопе, 1 колонка на мобильных; сайдбар sticky (top).
- [ ] Переписать шапку: flex-навигация, бургер-меню на Alpine (кнопка, `aria-expanded`,
  закрытие по Escape и по клику вне меню), логотип слева.
- [ ] Удалить float-хелперы `.left`/`.right`/`.clearfix` из разметки и CSS.
- [ ] Футер: flex-центрирование, ссылки с фокус-стилями, copyright.
- [ ] Пагинация: переписать как кнопки-чипы (активная страница выделена).

### Фаза 3 — Компоненты (3–5 дней)
- [ ] Карточки статей: заголовок, дата, рубрика/теги, hover-эффект, placeholder-скелетон.
- [ ] Сайдбар (`includes/sidebar.blade.php`): список рубрик/тегов — чипы с счётчиками.
- [ ] Формы (контакты, комментарии, auth): единые поля, лейблы, ошибки, кнопки.
- [ ] Комментарии: аватар, имя, дата, текстовый блок, разделители.
- [ ] Алерты/уведомления: перевести на токены, добавить dismiss.
- [ ] Страницы ошибок (404/500 и др.): единый шаблон с иконкой и кнопкой «На главную».
- [ ] Иконки: заменить FontAwesome на инлайн-SVG (спрайт) в ключевых местах.

### Фаза 4 — Адаптивность и доступность (2–3 дня)
- [ ] Переписать все `@media` на рабочую нотацию (`min-width` mobile-first), убрать опечатки.
- [ ] Проверить все экраны: 320/375/414/768/1024/1280/1920.
- [ ] Коснуться всей интерактивности: `:focus-visible`, `aria-*`, семантические теги.
- [ ] `prefers-reduced-motion`: отключать/упрощать анимации.
- [ ] Язык страницы и атрибуты `lang`, `title` на каждой странице.

### Фаза 5 — Тёмная тема (1–2 дня)
- [ ] Токены `[data-theme="dark"]` + `prefers-color-scheme`.
- [ ] Переключатель темы в шапке (Alpine, сохранение в localStorage, flash-of-wrong-theme скрипт в `<head>`).
- [ ] Проверка контраста всех компонентов в обеих темах.

### Фаза 6 — Производительность и кросс-платформенность (1–2 дня)
- [ ] Критический CSS (инлайн) или `@media print`-правила; минификация уже есть (Vite).
- [ ] `loading="lazy"` для изображений, `width/height` для предотвращения CLS.
- [ ] `font-display: swap` (или отказ от внешних шрифтов — системный стек).
- [ ] Тесты: Safari iOS/Android (через эмуляторы/реальные устройства), Chrome, Firefox, Edge, Safari macOS.
- [ ] Lighthouse: Performance/A11y/Best Practices/SEO >= 90.

### Фаза 7 — QA и полировка (1–2 дня)
- [ ] Регрессионное сравнение со скриншотами из Фазы 0.
- [ ] Проверка админки Orchid (не должна пострадать от изменений токенов).
- [ ] Проверка комментариев, форм, пагинации, фильтров рубрик/тегов.
- [ ] Удаление мёртвого CSS и неиспользуемых ассетов.

## 6. Кросс-платформенный чек-лист приёмки

| Платформа | Браузер | Что проверить |
|---|---|---|
| Windows/Linux | Chrome, Edge, Firefox | макет, формы, меню, пагинация |
| macOS | Safari, Chrome | шрифты, скругления, sticky-сайдбар |
| iOS | Safari | viewport, зум, тач-цели >= 44px |
| Android | Chrome | меню, формы, скорость |

## 7. Риски и открытые вопросы

- **Риск**: регрессия вёрстки на старых страницах (errors, auth, profile) — митигируется фазой QA и скриншотами.
- **Риск**: конфликт Tailwind-утилит и наследуемого SCSS — придерживаться `@layer`, не смешивать в одном элементе.
- **Риск**: тёмная тема ломает контраст изображений/кода — принять политику «тёмные темы для UI, контент — как есть».
- **Открытый вопрос**: оставить Tailwind как основной инструмент новых компонентов или полностью перейти на чистый SCSS? (рекомендация: Tailwind для новых + SCSS-модули для наследия).
- **Открытый вопрос**: нужен ли переключатель темы вручную или достаточно авто-режима ОС?

## 8. Definition of Done

1. Все пункты Фаз 0–7 выполнены; `max-widht` и прочие опечатки отсутствуют.
2. Сайт корректно отображается на 320px–1920px без горизонтального скролла.
3. Меню и формы работают без мыши (клавиатура, тач), зум не заблокирован.
4. Dark mode и light mode проходят проверку контраста (>= 4.5:1 для текста).
5. Lighthouse (Performance, A11y, Best Practices, SEO) >= 90 на главной и статье.
6. Админка Orchid и весь CRUD-функционал не затронуты.
7. План реализации оформлен как OpenSpec-change (proposal/design/tasks) перед началом кодинга.
