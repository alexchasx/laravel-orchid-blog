# Промт

Тебе нужно доработать репозиторий `https://github.com/alexchasx/laravel-orchid-blog` из обычного проекта в качественный шаблонный репозиторий (GitHub public template). Репозиторий — блог на Laravel + Orchid Platform. Цель: чтобы любой разработчик мог нажать «Use this template» и получить чистую основу для своего блога, а не чужой проект со специфичными данными.

### Очистить `.env.example`

Замени все реальные значения на пустые или на плейсхолдеры:

```
APP_KEY=
DB_DATABASE=
DB_USERNAME=
DB_PASSWORD=
SUB_LOGO=
```

Удали любые захардкоженные ключи, пароли, имена баз и пользовательские подзаголовки. Файл должен быть шаблоном конфигурации, а не копией боевого `.env`.

### Удалить lock-файлы

Удали `composer.lock` и `package-lock.json` из репозитория. Добавь их в `.gitignore`, если их там нет. Каждый новый проект из шаблона должен получать свежие версии зависимостей.

### Очистить миграции

Проверь миграции на наличие захардкоженных данных через `DB::table()->insert()` или аналоги. Если есть — перенеси их в сидеры из или удали. Миграции должны только создавать структуру таблиц.

### Удалить проектные файлы

Удали `_ISSUES.md` и любые другие файлы, специфичные для конкретного проекта (заметки, todo, черновики, скрипты деплоя под конкретный сервер).

## Возможности
- Перечисли, что уже работает из коробки (CRLG постов, категории, теги, медиа-загрузка, роли и т. д.)

## Что нужно поменять после создания
- `APP_NAME`, `APP_URL` в `.env`
- `SUB_LOGO` — подзаголовок сайта
- Название проекта в `composer.json` и `package.json`
- Favicon и логотип в `public/`
- Настройки Orchid в `config/platform.php`

### Обновить `composer.json`

- Измени `name` на `alexchasx/laravel-blog-template`

### Обновить `package.json`

- Измени `name` на шаблонный
- Очисти проектные скрипты, если есть специфичные (деплой на конкретный сервер и т. п.)

### Добавить `.gitattributes`

Создай `.gitattributes` с `export-ignore` для файлов, которые не нужны в новых проектах:

```gitattributes
.gitattributes export-ignore
.gitignore export-ignore
.editorconfig export-ignore
README.md export-ignore
```

###  Очистить публичные ассеты

Проверь `public/` на наличие специфичных файлов — favicon, логотипов, загрузок, скриншотов. Оставь только дефолтные файлы Laravel/Orchid. Если есть кастомные лого — замени на placeholder или удали и укажи в README, что нужно добавить свои.

###  Проверить config-файлы

Проверь `config/platform.php` и другие конфиги на захардкоженные значения: URL сайта, имя проекта, email администратора. Замени на дефолтные или на `env()` с пустым значением по умолчанию.

###  Финальная проверка

- Убедись, что в репозитории не осталось реальных паролей, ключей, токенов, email-адресов (кроме `admin@example.com` как дефолта)
- Проверь, что `php artisan key:generate` сгенерирует новый ключ (значение в `.env.example` пустое)
- Убедись, что после `composer install` + `migrate --seed` проект запускается с нуля без ошибок
- Проверь, что в git-истории нет утечек — если в коммитах раньше были реальные `.env` файлы, добавь их в `.gitignore` и удали из индекса через `git rm --cached`
